## 0. Current design (as of D-53, 2026-09-30)

> This file: current design, open items, decisions log (why each rule exists). Operational detail:

> The original v2 draft, reviews and full Q&A are in `HISTORY.md`; this summary and the decisions log win.

**Runs in** Claude Desktop (Claude Code), with Claude controlling Chrome (D-25). **Command:**
`/dev-ticket [N | pause [N]]`. **Credentials:** `AI_DEV_ENV\credentials.env`, git-ignored (Assembla
+ Jenkins). **Work files:** `DEV_TICKETS\{N}\` (D-31). **Jenkins** is used only to trigger the
staging deploy on the LOW path (D-8); everything else is the Assembla API + plain git.

| Step | What happens | Hard rules |
|---|---|---|
| 0 Start/resume | Resume from `state.json`, or from the HANDOVER attachment on another PC | Reassigned developer may resume (D-35) |
| 1 Pick | Your one Dev In Process ticket in a `_CURRENT` milestone | 0 / >1 / not yours / wrong status / wrong milestone → stop (D-1) |
| 2 Check | Snapshot; detail checklist; staging attributes; Epic | Missing detail → questions + Missing Implementation Details (D-3). Attributes (Story, Node WF, WF tag, active Epic) fixed by the workflow before any branch (D-12, D-13). Developer picks the Epic, ranked by functional area (D-14, D-15) |
| 3 Branch | `FB_N` from `origin/master`, plain git | No commits; local-only files ignored (D-16, D-27) |
| 4 Understand | BRIEF.md; every chat answer recorded (D-40) | DB changes go on the milestone's DB **Story** branch `FB_D` in `C2M_CI_DB` (D-18, D-21, D-23) |
| 5 Plan | PLAN.md: tasks with test + AC; UI checks | Tier always confirmed; can only go up (R-1, `state` command) |
| 6 Build | Test first, per task | Max 3 fix attempts |
| 7 Verify | **7a gates → 7b risk → 7c master → 7d functional checks (Chrome) → 7e independent review** (run order D-48; letters renumbered in run order since) | Risk floors: DB SP/DML ≥ MEDIUM, DDL HIGH (D-20), canvas ≥ MEDIUM unless label/color (D-26). Review = self-contained REVIEW.md, security finding ≥ Medium (D-41, D-42) |
| 8 Hand off, STANDARD | Developer: commit → push → pull master → (gates) → push; then SUMMARY comment + **Code Review** (D-2, D-47) | Claude never commits on this path (D-36) |
| 8 Hand off, LOW | One **"go"** (D-10): Claude commits → push → pull master → gates → push → review + summary comments → Code Review → Dev Done → DevOps Staging → deploy if first in queue (D-11), `GENERATE_QA_TESTCASES=false` (D-44) → QA Queue → UI checks on staging, developer signs in (D-28, D-45) | Queued deploy resumable (D-48). Any failure → stop or fall back to STANDARD |
| Pause | Developer WIP commit (+DB) → HANDOVER.md attached + comment → Dev Queue (D-32–D-40) | |
